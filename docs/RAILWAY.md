# Развёртывание SafeNet KZ на Railway

Репозиторий: `taraz-08/safenet-kz`, ветка `main`. Сборка, запуск и проверка готовности задаются в настройках сервиса Railway через плагин или панель управления.

На 25.10.2026 Railway больше не разрешает подключать `railway.json` / `railway.toml` к новым сервисам. Поэтому устаревший файл удалён из репозитория. Для будущего управления инфраструктурой из кода используется `.railway/railway.ts`; при работе в общем проекте нужен именованный partial, чтобы не менять другие сервисы.

| Настройка сервиса | Значение |
|---|---|
| Builder | Dockerfile |
| Dockerfile Path | `Dockerfile` |
| Root Directory | `/` |
| Build Command | `npm run build` |
| Start Command | `npm start` |
| Healthcheck Path | `/api/health` |
| Healthcheck Timeout | 120 секунд |
| Restart Policy | On Failure, максимум 3 попытки |

## Настройка сервиса

1. Подключить GitHub-репозиторий к сервису Railway. Корень проекта — `/`.
2. Корневой `Dockerfile` собирает интерфейс на Node.js 22: `npm ci --include=dev`, затем `npm run build`. В отдельный рабочий образ копируются готовый интерфейс, сервер, модель, метрики и корпус. DevDependencies нужны только на этапе сборки; `.dockerignore` исключает секреты, локальные находки, браузерные профили и видео.
3. Добавить Volume с точкой монтирования `/data`. Приложение использует `RAILWAY_VOLUME_MOUNT_PATH` для случаев, решений аналитика и состояния поисковых модулей. Не монтировать Volume поверх `/app/data`: там находятся модель, метрики и синтетический корпус из репозитория.
4. Для публичного чтения с входом администратора задать отдельный секрет `SAFENET_ADMIN_CODE` в Variables. Код открывает редактирование, настройки и сохранение только вошедшему посетителю. Существующий `SAFENET_ACCESS_KEY` по-прежнему закрывает весь сайт HTTP Basic: любое имя пользователя и этот ключ в качестве пароля. Если заданы оба секрета, Basic требуется независимо от административной сессии. Использовать HTTPS; секреты не записывать в Git.
5. Создать публичный домен Railway. `PORT`, адрес прослушивания `0.0.0.0` и домен определяются автоматически. Healthcheck: `/api/health`, ожидается HTTP 200 и `ok:true`.
6. Оставить одну реплику: JSON-хранилище не рассчитано на одновременную запись несколькими процессами. Для нескольких реплик нужен переход на БД (GitHub Issue #7).

Без Basic-ключа и административной сессии сайт работает в режиме `public_read_only`: посетители видят очередь и объяснения, проверяют текст или скриншот без сохранения. Изменение решений, настроек и стартовых точек поиска запрещено сервером. После входа `/api/health` возвращает `mode:hosted_admin` для этого посетителя; остальные продолжают читать публичный сайт. Health также содержит `adminLoginEnabled` и `adminSessionExpiresAt` (ISO-время или `null`). Локальный режим и HTTP Basic сохраняют прежние права. Реальные находки имеют отдельное происхождение.

API входа: `GET /api/auth/session` возвращает `{enabled,authenticated,expiresAt}`; `POST /api/auth/login` с JSON `{code}` возвращает 200 `{authenticated:true,expiresAt}`, неверный код — 401, отсутствие настройки — 503; `POST /api/auth/logout` возвращает 200 `{authenticated:false}` и отзывает текущую сессию. Сессионная cookie случайная, непрозрачная, `HttpOnly; SameSite=Strict; Path=/`; на хостинге добавлены `Secure` и префикс `__Host-`. Она действует 8 часов без продления, хранится только в памяти сервера и перестаёт действовать после перезапуска. Код и токен не возвращаются в JSON и не журналируются. У вошедшего администратора `/api/analyze` сохраняет случай с HTTP 201; у гостя остаётся 200 и `stored:false`.

Вход принимает JSON до 1 КиБ (код в конфигурации — до 512 байт). Лимиты: 10 попыток за 5 минут на адрес TCP-соединения и 100 за 5 минут на процесс; при превышении — 429 с `Retry-After`. Заголовкам пересылки адреса сервер не доверяет, поэтому посетители за одним reverse proxy разделяют лимит. Максимум 128 активных сессий; заполнение возвращает 503 и не отзывает чужие сессии. Вход и выход проходят те же проверки Host, Origin и Fetch-Site, что и остальные API. Эти права не отменяют запреты демо в `liveOnly`.

На хостинге по умолчанию действует `liveOnly` (`/api/health` возвращает `liveOnly:true`), в том числе с ключом доступа. При первом запуске существующий файл случаев архивируется рядом как `cases.json.pre-live-only.bak` без перезаписи архива, затем удаляются только записи с `demo===true`. Все остальные случаи, их идентификаторы, анализ и решения аналитиков сохраняются. Демо-данные не добавляются, сохранённый включённый демо-поток не возобновляется. `/api/demo` и изменения `/api/pipeline` запрещены; чтение потока возвращает `liveOnly:true`, `running:false`, нулевые счётчики и пустой журнал. `/api/networks` строится по настоящим случаям. Маршруты `/demo-feed`, `/demo/content.js` и `/demo-feed.html` возвращают 404; `/pitch` остаётся доступен. Локальный режим сохраняет демо для автономного показа.

Для автопоиска публичных Telegram-каналов задайте `SAFENET_TELEGRAM_SEEDS` в Variables: публичные имена, `@имена` или ссылки `https://t.me/…`, разделённые запятыми или переводами строк. Имена нормализуются, повторы удаляются; максимум 50 уникальных каналов. Закрытые приглашения, некорректные значения или превышение лимита останавливают запуск с ошибкой конфигурации. Пустая переменная не добавляет стартовых точек. Изменения применяются после перезапуска сервиса.

Эти стартовые точки работают и в `public_read_only`, без ключа доступа и разрешения посетителям изменять данные. Они не записываются в список аналитика и не добавляются в справочные/новостные источники профиля Казахстана. Удаление канала из переменной снимает его приоритет и право расширять поиск как стартовой точки, если он не остаётся в списке аналитика или среди включённых источников мониторинга. Ранее найденные каналы и случаи сохраняются; дальнейшие проверки подчиняются обычным правилам автопоиска.

`SAFENET_SOCIAL_ENABLED=1` — явное включение автопоиска Instagram/TikTok оператором; `0` выключает его. Значение применяется при запуске до планировщика и сохраняется. Без переменной сохраняется прежняя настройка, а на новой установке поиск выключен; другие значения, включая пустую строку, вызывают ошибку запуска. Для публичного сайта это не открывает API записи.

`SAFENET_DATA_DIR` позволяет явно переопределить каталог состояния. Без Volume данные в контейнере не гарантированно сохраняются после развёртывания. Модель и метрики читаются из репозитория независимо от каталога состояния.

## Что доступно в облаке

- Интерфейс, объяснимый анализ текста, пакетный API и OCR скриншотов в браузере.
- Поиск публичных Telegram-каналов и очередь ручной проверки, если Telegram доступен из региона сервиса. Неудачные запросы видны в журнале.
- Образ устанавливает Debian Chromium и шрифты (`CHROME_PATH=/usr/bin/chromium`). Для изолированного Linux-контейнера под root задан `CHROME_NO_SANDBOX=1`; локальный браузер сохраняет sandbox. `SAFENET_BROWSER_PROFILE_DIR=/tmp/safenet-browser` держит профиль и cookies вне Volume с данными; дисковый кеш ограничен 10 МБ. Instagram/TikTok включаются через `SAFENET_SOCIAL_ENABLED=1`: только публичные страницы без входа, без маскировки браузера и обхода капчи. Капча или требование входа ставит платформу на паузу. Наличие Chromium не гарантирует успешную проверку: ограничения платформы и ошибки видны в журнале.
- Локальные Ollama/Whisper и захват медиа расширением не переносятся в Railway автоматически. Расширение настроено на локальный сервер. Доступность этих функций показана в интерфейсе; облачная версия не обещает анализ полного видео.

После развёртывания проверить загрузку интерфейса, `/api/health`, `/api/metrics`, одну ручную проверку и сохранение решения после перезапуска приватного сервиса. Зафиксировать URL и deployment ID только после успешной проверки.

Справка Railway: [переход на Infrastructure as Code](https://docs.railway.com/infrastructure-as-code#migrating-from-config-as-code), [Volumes](https://docs.railway.com/guides/volumes).
